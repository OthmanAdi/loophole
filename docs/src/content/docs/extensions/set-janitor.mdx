Set Janitor is the whole-set hygiene sweep. The bundled command finds empty tracks,
placeholder names, and clips that overrun their loop. You tick which to fix; it renames or
deletes only the selected items. Color enforcement is an opt-in core capability that requires a
caller-supplied complete, verified palette.

## What it does

It reads the whole Set, detects a list of issues, and groups them. You choose
which groups to fix. Value edits share one transaction when present. Deletes are off by default,
and every selected structural deletion runs as its own later transaction.

## Right-click path

Right-click a Scene, then select **Clean Up Set…**. A checklist dialog shows the issues found,
grouped: "3 empty tracks", "7 unnamed clips", and "2
clips overrun their loop". Tick the groups to fix, then
press Fix selected. Destructive items (delete a track or clip) are flagged and
unchecked by default.

<Aside type="caution" title="Current verification">
  Detection, selection, ordered structural deletes, and the handler plan are exercised against the
  fake. The menu, real SDK deletes, and Live undo history are `NOT_RUN_NO_LIVE`. Use a disposable
  copy of a Set for the first runtime check.
</Aside>

## Beta limit

Set Janitor sweeps the whole Set for mess and fixes what you tick: empty tracks,
placeholder names, and clips that overrun their loop. It
is not a clip renamer (Ableton's own RNMR does that, and better, for
content-aware MIDI naming); Janitor is the structural sweep around it. Deleting a
track or clip is permanent within the Set until you undo, so those fixes are off
by default and you opt into them. The bundled UI has no complete verified Live palette, so color
diagnosis is disabled. A custom caller may opt in only by supplying a complete verified palette,
which is used for both detection and recoloring. Value changes share one transaction; every
structural deletion creates a separate undo entry. It cannot relink missing samples, consolidate
the project folder, or fix automation, because the beta exposes none of those. It
is user-invoked. Confirm the actual Live undo history during the E2E gate.
