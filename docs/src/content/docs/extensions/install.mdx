The Loophole Kit registers five right-click actions from one extension package. They share
the same core as the bridge. Undo behavior is checked separately in Live.

<Aside type="note" title="Install from source">
  There is no released `.ablx`. Licensed SDK users can package one locally and then run the evidence
  gates below.
</Aside>

## Prerequisites

- **A supported current Ableton Live beta.** Dev Mode is required only for `start:live`
  hot-loading, not for installing a packaged `.ablx` through Settings.
- **The Extensions SDK and CLI tarballs** from your own Ableton Beta Program
  access. They are not redistributable, so Loophole does not ship them.
- **Node 24.14.1 or newer** and **pnpm 10**.

## Build and install

<Steps>

1. Clone and install the workspace.

   ```bash
   git clone https://github.com/OthmanAdi/loophole.git
   cd loophole
   pnpm install --frozen-lockfile --ignore-scripts
   ```

2. Add your local SDK and CLI tarballs (do not commit the resulting manifest or
   lockfile changes).

   ```bash
   pnpm add file:/abs/path/to/ableton-extensions-sdk-1.0.0-beta.0.tgz --filter @othmanadi/loophole-extension
   pnpm add -D file:/abs/path/to/ableton-extensions-cli-1.0.0-beta.0.tgz --filter @othmanadi/loophole-extension
   ```

3. Package the production `.ablx`.

   ```bash
   pnpm --filter @othmanadi/loophole-extension run package:live
   ```

4. In Live, open Settings, then Extensions, add the built `.ablx`, and restart
   Live.

</Steps>

The same install carries all five extensions and the bridge, because they ship in
one extension. Each appears as its own right-click action.

## Verify it worked

<Steps>

1. Record the `.ablx` filename, SHA-256, manifest, SDK and CLI versions, exact Live build,
   operating system, and install path.
2. Copy `ExtensionHost.txt` and `Log.txt` immediately after the load attempt. Preserve the
   activation output and complete exception stacks.
3. Confirm all five actions appear, `bridge.json` is created, authentication rejects a missing
   token, and a real client can call `live_get_song_overview`.
4. Run every action in a disposable Set and record its actual Live undo entries. For Session to
   Song, compare Live with the receipt: 0 for a no-op, 2 for cue-only, or 3 for a run that clears,
   creates, and populates.

</Steps>

Use the full [E2E checklist](https://github.com/OthmanAdi/loophole/blob/main/packages/extension/E2E_CHECKLIST.md).
The current package and Live-runtime gates are `NOT_RUN` and `NOT_RUN_NO_LIVE`. If actions are
missing, collect the exact logs before changing the package or template, then see
[Troubleshooting](/mcp/troubleshooting/).
